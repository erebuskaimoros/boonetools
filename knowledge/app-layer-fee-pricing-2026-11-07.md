## Why the USD bars are empty

The 09:15, 09:20, 09:25, and 09:30 UTC scheduler records all report successful
jobs but pricing errors: zero weeks loaded, zero events priced, one pending
week, and a provider cooldown for `service:gateway.liquify.com/api=dedicated`
following `This operation was aborted`. Acquisition metrics show zero actual
`/history/rune` attempts and one cooldown skip per run. This is an ordinary
timeout cooldown, not evidence of a daily quota being exhausted.

`loadRujiraRunePrices` selects only the first configured base. `/history/rune`
does not have its own family in `shared/midgard.js`'s cooldown scope selection;
it uses the generic service bucket. The exact caller that originally set that
shared timeout was not established; the VS v1 actions timeout has its own
`:actions` scope and should not be conflated with it.

A bounded direct public Liquify request for the November 2–9 weekly RUNE
history succeeded with HTTP 200 and `runePriceUSD=0.6044324476426243`. This
proves a matching price interval is available on that public route, not that
the dedicated route was healthy or that either is an independent provider.

The chart uses the zero USD placeholders as observed numeric values, so it
displays both $0 bars and complete coverage. The contract note only says
“fees processing”; it does not explain the missing valuation.

## Follow-up

Reproduce pricing cooldown isolation and missing-USD coverage behavior in
their existing module tests before fixing. Isolate RUNE-history acquisition,
provide bounded recovery with validated same-period prices, and expose
unpriced RUNE/fee counts rather than $0 or complete coverage. Preserve saved
events, valuation provenance, counters, and legacy recovery state. A direct
successful price read is not permission to silently replace historical price
methodology or reset provider protection.

## Authorized repair

The user requested fixing pricing cooldowns, displaying unpriced fees rather
than $0, and deployment after checks. Work continues in the existing
`feat/app-layer-vs-tracking` worktree, fast-forwarded to production main.

Four reproductions failed before implementation: generic cooldown blocking
`/history/rune`, failure to retry a short pricing cooldown, invented zero fee
chart buckets, and unpriced observations counted in USD summaries. A real
PostgreSQL fixture additionally reproduced incomplete USD sums being returned
as complete totals.

The repair isolates RUNE history, preserves the configured primary and price
interval/cache identity, and shares two recovery retries/120 seconds of wait
across each loader invocation. Every retry uses ordinary provider admission;
rate limits, Retry-After, budgets and cancellation remain authoritative.

The API separates native fees, known USD subtotals and unpriced fee counts.
The frontend preserves unknown values through fee bars, cumulative values,
rolling/period aggregations, totals and combined 01+03 charts. Gaps in legacy
history remain unknown; this release does not reclassify them as zero or
restart historical acquisition. Price recovery only values saved events.
